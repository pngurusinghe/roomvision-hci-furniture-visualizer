# Requirements Specification – RoomVision

## 1. Overview
This document defines the functional and non-functional requirements for the RoomVision furniture room visualisation application. The system is designed to support furniture designers during in-store consultations by allowing them to create, visualise, and modify room layouts using interactive 2D and 3D views.

---

## 2. Target Users
The primary users of the system are professional furniture designers who work directly with customers in retail environments.

### User Characteristics
- Experienced in interior or furniture design
- Basic computer literacy
- Limited time per customer consultation
- Require clear and responsive visual feedback

---

## 3. Functional Requirements

FR1. The system shall allow designers to securely log in to the application.

FR2. The system shall allow designers to create a virtual room by entering room dimensions and selecting a colour scheme.

FR3. The system shall display a 2D top-down view of the room layout.

FR4. The system shall allow designers to add furniture items to the room layout.

FR5. The system shall allow designers to move and arrange furniture items using drag-and-drop interaction.

FR6. The system shall allow designers to scale furniture items proportionally to fit the room dimensions.

FR7. The system shall allow designers to change colours of individual furniture items or the entire room.

FR8. The system shall allow designers to convert a 2D layout into a 3D visualisation.

FR9. The system shall provide immediate visual feedback for all user actions (e.g. scaling, colour changes, saving).

FR10. The system shall allow designers to save, edit, and delete room designs.

---

## 4. Non-Functional Requirements (HCI-Focused)

NFR1. The interface shall be intuitive and require minimal training to use.

NFR2. The system shall provide consistent navigation and interaction patterns across all views.

NFR3. The system shall render 2D and 3D views with minimal latency.

NFR4. The system shall follow accessibility guidelines regarding colour contrast and font size.

NFR5. The system shall provide clear error messages and undo options to support error recovery.

NFR6. The system shall support efficient workflows to allow designers to complete tasks within a short consultation time.

---

## 5. Scope Definition

### In Scope
- Designer-focused application
- 2D and 3D visualisation of rooms
- Furniture manipulation and visual adjustments
- Usability-driven design and testing

### Out of Scope
- Customer login or accounts
- Online purchasing or payments
- Advanced physics or photorealistic rendering
- AR or VR integration

---

## 6. Success Criteria
The system will be considered successful if designers can efficiently create and visualise room layouts, receive clear feedback for their actions, and express confidence in using the system during customer consultations.
